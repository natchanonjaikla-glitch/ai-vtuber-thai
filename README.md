# AI VTuber (LLM ในเครื่อง + เสียงไทย + อวตาร Live2D)

VTuber ที่ขับเคลื่อนด้วย LLM ที่รัน **ในเครื่องนี้** (offline) พูดคุยภาษาไทย มีเสียงพูด
อวตารใน VTube Studio ขยับปาก+ทำสีหน้าตามอารมณ์ ค้นเว็บ/เช็กอากาศได้ และเมื่อเจองาน
เขียนโค้ดที่ยากมาก จะส่งต่อให้ **Claude Code** (`claude -p`) ทำแทนโดยอัตโนมัติ

```
พิมพ์ข้อความ
   │
   ▼
router (regex trigger คำสั่งไทย)
   ├─► "เรียก claude ..."   ─► claude -p (subprocess) ─► สรุปผล
   ├─► "อากาศ..."           ─► Open-Meteo API (ไม่ผ่าน LLM เลย)
   ├─► "ค้นหา..."           ─► DuckDuckGo → อ่านทั้งหน้าเว็บ → LLM สรุป
   └─► อื่น ๆ               ─► LLM ในเครื่อง (LM Studio)
                                  │  ปล่อยมาร์กเกอร์ [[EMOTION:]] [[SEARCH:]] [[DELEGATE_TO_CLAUDE:]] เองได้
                                  ▼
                         TTS ภาษาไทย (Piper/Edge/MMS/F5)
                                  │
                                  ▼
                         เล่นเสียง + ขับปาก(ตามสระ)+สีหน้า ผ่าน VTube Studio API (30fps ต่อเนื่อง)
```

เวอร์ชันนี้ (v1): **พิมพ์แชท + เสียงออก + ปากขยับตามสระ + สีหน้าตามอารมณ์ + ค้นเว็บ/อากาศ**
ยังไม่รับเสียงไมค์ (STT อยู่ใน v2)

## เทคนิคที่ใช้ (สรุปสำหรับคนอยากรู้ว่าทำยังไง / แก้ปัญหาอะไรมาบ้าง)

### 1) สมอง — local LLM ผ่าน LM Studio
- ใช้ LM Studio เพราะ backend **Vulkan** รองรับ AMD GPU บน Windows ได้ทันที (ROCm PyTorch ไม่มีบน Windows)
- คุยผ่าน **OpenAI-compatible API** (`openai` SDK ธรรมดา ชี้ `base_url` ไป `localhost:1234/v1`) — สลับโมเดล/สลับเป็น Ollama ทีหลังได้โดยไม่ต้องแก้โค้ด
- **บทเรียนสำคัญ: โมเดลใหญ่กว่า ≠ ดีกว่า ถ้า VRAM ไม่พอ** — ทดสอบจริง gemma-3-12b (7.6 GB) ล้น VRAM ไป RAM 2.8 GB ทำให้เหลือ **5 tok/s** ส่วน Typhoon2-8B (4.6 GB, พอดี VRAM) ได้ **47 tok/s** (เร็วกว่า 9 เท่า) — วัดด้วย `scripts/bench_model.py`
- โมเดล "คิดก่อนตอบ" (reasoning model อย่าง gemma-4) เสีย token ไปกับ `reasoning_content` เกือบหมด (99% ในการทดสอบ) เหลือคำตอบจริงนิดเดียว → เลือกโมเดลที่ไม่ reasoning สำหรับงานสนทนาสด

### 2) เสียงพูดไทย — เลือกเอนจินตาม trade-off ความเร็ว/คุณภาพ/offline
- **Coqui XTTS-v2 ไม่รองรับภาษาไทย** (เช็กจาก docs แล้ว 16-17 ภาษาไม่มีไทย) — เป็นสมมติฐานเริ่มต้นที่ผิด ต้องหาทางอื่น
- ลองสี่เอนจิน วัดผลจริงทุกตัว (RTF = เวลาสังเคราะห์ / ความยาวเสียง ยิ่งน้อยยิ่งเร็ว):

  | เอนจิน | RTF (ยิ่งน้อยยิ่งเร็ว) | offline | หมายเหตุ |
  |---|---|---|---|
  | **Piper** (ค่าเริ่มต้น) | 0.08 | ใช่ | เร็วสุด ธรรมชาติพอควร ต้องพึ่ง `tltk` แปลงอักษรไทย |
  | Edge-TTS | 0.12 | ไม่ ต้องต่อเน็ต | ธรรมชาติที่สุด (Microsoft neural) |
  | MMS-TTS | 0.23 | ใช่ | เสียงเดียว หุ่นยนต์นิด ๆ แต่ติดตั้งง่ายสุด (fallback) |
  | F5-TTS-THAI | ~83 | ใช่ | โคลนเสียงได้ แต่ ~6 นาที/ประโยคบน CPU ไม่มี CUDA — อัดล่วงหน้าเท่านั้น |

- **Piper ต้องการ `tltk`** (ตัวแปลงอักษรไทย→เสียง) ซึ่ง pip แก้ dependency ให้เองไม่ได้ (pin `scikit-learn~=1.2` ที่ไม่มี wheel สำหรับ Python 3.12) ต้องลงแบบ `--no-deps` แล้วเติม `nltk` + `sklearn-crfsuite` + `gensim` + `unicode-rbnf` เอง
- **F5-TTS ต้อง pin `torch==2.8.0` + `torchaudio==2.8.0` คู่กันเป๊ะ** — ปล่อยให้ pip เลือกเองจะได้ `torchaudio` ที่ผูกกับ `torchcodec` ซึ่งต้องการ FFmpeg shared DLL (ที่ winget ให้มาเป็น static build) ทำให้พังตอนใช้งานจริง
- **เอนจินเสียงไทยตัดตัวอักษรอังกฤษทิ้งเงียบ ๆ** (ไม่ error แค่หายไปจากเสียง) จึงมีตัวแปลงคำอังกฤษเป็นคำอ่านไทยก่อนเข้า TTS เสมอ (เช่น VTuber เป็นวีทูเบอร์, ตัวย่อพิมพ์ใหญ่สั้น ๆ อย่าง GPU สะกดทีละตัวเป็นจีพียู)

### 3) อวตาร — VTube Studio Plugin API (WebSocket)
- **ต้องฉีดค่าพารามิเตอร์ต่อเนื่องตลอดเวลา (30fps)** ไม่ใช่ฉีดครั้งเดียวตอนพูด — VTS ถือว่าค่าที่ฉีดเป็นค่าชั่วคราว พอหยุดส่งจะกลับไปใช้ค่าจาก face-tracking ทันที `AvatarDriver` เลยเป็น task เดียวที่ยิงค่าทุกพารามิเตอร์ (ปาก+สีหน้า+ท่าทาง) รวมกันทุกเฟรม ไม่ใช่หลาย task แยกกัน
- **บั๊กที่เจอ:** ตัว RPC client เดิมสมมติว่า "ข้อความถัดไปที่รับจาก socket คือคำตอบของ request ที่เพิ่งส่ง" ใช้ได้ตอนไม่มีอะไรคุยพร้อมกัน แต่พอ lip-sync ยิง 30 req/วิ พร้อมกับโค้ดอื่นถาม RPC จะได้คำตอบผิดตัว (อ่านค่าพารามิเตอร์ได้ None ทั้งที่ฉีดสำเร็จจริง) แก้ด้วย reader task เดียวที่จับคู่คำตอบด้วย `requestID` ผ่าน `asyncio.Future`
- **ปากขึ้นรูปตามสระ ไม่ใช่แค่อ้า-หุบ:** Piper ไม่ให้ phoneme alignment (จังหวะเวลาของแต่ละเสียง) มาด้วย เลยวิเคราะห์เอาจากคลื่นเสียงจริง — FFT หา peak ของ F1/F2 (ฟอร์แมนต์) ต่อเฟรม เทียบระยะห่างแบบ log-frequency กับค่าฟอร์แมนต์อ้างอิงของสระ อา/อี/อู/เอ/โอ แล้วยกกำลัง 3 เพื่อให้สระที่ชนะเด่นชัด ไม่เบลอปนกัน
- **สีหน้า/อารมณ์:** โมเดลปล่อยมาร์กเกอร์ `[[EMOTION: happy]]` เอง (มี fallback เดาจากคำไทยถ้าโมเดลไม่ใส่) ค่าพารามิเตอร์ของแต่ละอารมณ์ค่อย ๆ ผสมเข้าเป้าหมาย (blend factor) ไม่ใช่สลับทันที และมีขยับหัว/หายใจคาบไม่ลงตัวกันและกะพริบตาสุ่มตอนอยู่เฉย กันดูค้างแข็ง

### 4) Router แบบ marker — ให้โมเดลตัดสินใจเองว่าจะทำอะไรต่อ
โมเดลปล่อยมาร์กเกอร์ท้ายข้อความเพื่อสั่งงานระบบอื่น โดยไม่ต้อง fine-tune หรือใช้ function calling ที่โมเดลเล็กมักทำพลาด:
- `[[EMOTION: happy]]` เปลี่ยนสีหน้าอวตาร
- `[[SEARCH: คำค้น]]` ไปค้นเว็บมาสรุปให้
- `[[DELEGATE_TO_CLAUDE: งาน]]` ส่งงานให้ `claude -p`

Router มี "ทางลัด" คู่ขนาน — ผู้ใช้พิมพ์คำ trigger ตรง ๆ (เช่น "เรียก claude", "อากาศ...") ก็ข้ามโมเดลไปเรียกระบบนั้นได้เลย ไม่ต้องรอโมเดลตัดสินใจ

### 5) ค้นเว็บ — สองบั๊กจริงที่ทดสอบจับได้
- **บั๊ก 1 (ร้ายแรงสุด):** snippet ของ DuckDuckGo เป็นแค่คำโปรยเว็บ ไม่มีตัวเลข/ข้อเท็จจริง โมเดลเลยเติมช่องว่างด้วยความจำเก่าที่จำผิด — ถามราคาทองได้คำตอบ 29,500 บาท (ราคาจริง 68,450) ตอบผิดแบบมั่นใจมาก แก้ด้วยการดึงเนื้อหาเต็มจากหน้าเว็บจริง (ไม่ใช่แค่ snippet) และสั่ง prompt ตรง ๆ ว่าห้ามใช้ความจำเดิม โดยเฉพาะตัวเลข/ราคา/วันที่ เพราะความจำผิดแน่นอน
- **บั๊ก 2:** หน้าแรกที่ดึงมาบางทีเป็นเมนู/สารบัญเว็บ ไม่มีข้อมูลจริง โมเดลเลยลอกหัวข้อมาตอบ (ถามราคาน้ำมันได้คำตอบเป็นชื่อบทความ) แก้ด้วยการให้คะแนนความมีประโยชน์ของแต่ละหน้า (ความหนาแน่นของตัวเลข + คำจากคำค้นที่เจอ) แล้วเรียงหน้าที่มีข้อมูลจริงขึ้นก่อน หน้าที่ไม่มีอะไรเลยถูกทิ้ง
- **ความเร็ว:** `ddgs` ใช้ `backend="auto"` เป็นค่าเริ่มต้นซึ่งไล่ลองทีละ backend (2-10 วิ) พอ pin backend ตรง ๆ (google) เหลือ 0.4 วิ เร็วขึ้นราว 20 เท่า รวมกับตัดหน้าเว็บที่โหลดช้า (deadline รวม ไม่รอหน้าที่ช้าสุด) และข้ามโดเมนที่รู้อยู่แล้วว่าโหลดด้วย JS (facebook, youtube, ...)

### 6) อากาศ — เลี่ยง LLM ไปเลยเมื่อมี API ตรงที่เชื่อถือได้กว่า
เว็บพยากรณ์อากาศเกือบทั้งหมด render ตัวเลขด้วย JavaScript ทำให้ค้นเว็บแบบข้อ 5 ใช้ไม่ได้ (ดึงหน้ามาได้ HTML เปล่า) แก้ด้วยการข้ามโมเดลไปเลย — เรียก Open-Meteo (geocoding + forecast, ฟรี ไม่ต้องมี key) แล้วประกอบประโยคจากตัวเลขที่ API ให้มาโดยตรง เร็วกว่า (~2.5 วิ เทียบกับค้นเว็บ+LLM 10-20 วิ) และไม่มีทางหลอนเพราะไม่ผ่าน LLM เลย

### 7) เรื่องจุกจิกของ Windows ที่กัดจริง
- คำสั่ง `python run.py` ธรรมดาใช้ Python ของระบบซึ่งไม่มีแพ็กเกจ (อยู่ใน `.venv`) → `run.py` เช็กก่อนรันจริง ถ้าใช้ผิดตัวจะบอกวิธีแก้แทนที่จะโยน traceback ยาว ๆ
- Terminal เริ่มต้นของ Windows ใช้ codepage (cp1252/cp874) ไม่ใช่ UTF-8 → ตั้งค่าใน `run.py` ก่อนอย่างอื่นทั้งหมด
- VRAM เต็มง่ายกว่าที่คิด — แอปพื้นหลังอย่าง Voicemod/Discord/เบราว์เซอร์ กิน VRAM รวมกันหลัก GB และ LM Studio จำโมเดลตัวก่อนหน้าไว้ (JIT-load) ถ้าไม่ unload เอง ทำให้ค่อย ๆ ล้นแล้วช้าลงโดยไม่มีสัญญาณเตือน — เช็กด้วย `lms ps` เป็นระยะ

## ติดตั้งครั้งแรก

### 1) Python env + แพ็กเกจหลัก
```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
# ถ้าจะลงเครื่องใหม่ให้เป๊ะเหมือนเดิม:  pip install -r requirements-lock.txt
```

### 2) LM Studio (สมองของ VTuber)
1. โหลด + ติดตั้งจาก https://lmstudio.ai เปิดแอปครั้งแรกกดผ่าน onboarding
2. Settings → เลือก runtime **Vulkan** (การ์ด AMD ต้องเห็นชื่อการ์ดตัวเอง)
3. ค้น + ดาวน์โหลดโมเดล GGUF ที่พอดี VRAM ที่เหลือ (ดูข้อ 1 ในหัวข้อเทคนิคด้านบน — ใหญ่เกินจะช้าลงหลักสิบเท่า ไม่ใช่แค่ช้าลงนิดหน่อย):
   - `CT-Ati/llama3.1-typhoon2-8b-instruct-Q4_K_M-GGUF` — ภาษาไทยดีที่สุด (~4.9 GB)
   - `bartowski/Qwen2.5-7B-Instruct-GGUF` — สำรอง
4. แท็บ Developer → โหลดโมเดล → Start Server (พอร์ต 1234)
5. เอาชื่อโมเดล (ตามที่ LM Studio แสดง เช่น `llama3.1-typhoon2-8b-instruct`) ไปใส่ `config.yaml` → `llm.model`

### 3) VTube Studio (อวตาร) — ต้องลงเอง เป็นเกมใน Steam
1. ติดตั้งจาก Steam (ฟรี)
2. Settings (ไอคอนเฟือง) → เลื่อนหา Start API (allow plugins) → เปิด (พอร์ต 8001)
3. โหลดโมเดล Live2D ตัวอย่างที่แถมมา (เช่น Akari/Hiyori) ที่มีพารามิเตอร์ปากมาตรฐาน
4. ครั้งแรกที่รันแอปนี้ จะมี popup ใน VTube Studio → กด Allow (token เก็บไว้ที่ `.vts_token`)
   - ถ้า popup ค้าง/ไม่เด้ง ให้รัน `python scripts/vts_auth.py` แยกต่างหาก (รอได้ 5 นาที)

### 4) ffmpeg (สำหรับ F5-TTS)

```powershell
winget install Gyan.FFmpeg
```

### 5) Claude Code CLI (ตัวช่วยงานโค้ดยาก)

### 6) เสียงตัวละคร F5-TTS-THAI (ออปชัน — ใช้ Piper เป็นค่าเริ่มต้นอยู่แล้ว)

|---|---|---|---|---|
| RTF (ยิ่งน้อยยิ่งเร็ว) | 0.08 | 0.12 | 0.23 | ~83 |

## แก้ปัญหา

- **"ต่อ LM Studio ไม่ได้"** เปิดแอป LM Studio → Developer → Start Server เช็กว่าชื่อ `llm.model` ตรงกับที่โหลด
- **ตอบช้าผิดปกติ (เกิน 10-20 วิ ต่อประโยค)** เช็ก `lms ps` ว่ามีโมเดลโหลดซ้อนกันไหม (LM Studio ชอบ JIT-load โมเดลเก่ากลับมา) แล้ว `lms unload --all` ก่อนโหลดโมเดลที่ต้องการใหม่
- **ปากไม่ขยับ** VTube Studio เปิด API หรือยัง? โมเดลมีพารามิเตอร์ `MouthOpen` ไหม (ถ้าใช้ชื่ออื่นให้แก้ `avatar.mouth_param`) กด Allow popup แล้วหรือยัง ลอง `python scripts/test_avatar.py`
- **ไม่มีเสียง** เช็ก default output device ของ Windows ด้วย `python -c "import sounddevice; print(sounddevice.query_devices())"`
- **F5 ติดตั้งไม่ผ่าน หรือชน torch** ข้ามไปก่อน ใช้ piper หรือ mms ได้เต็มรูปแบบ
- **ภาษาไทยเพี้ยนในเทอร์มินัล** ใช้ Windows Terminal `run.py` ตั้ง UTF-8 ให้แล้ว
- **`claude` สั่งงานแล้ว error** รัน `claude` เปล่า ๆ ครั้งนึงเพื่อ login ให้เรียบร้อยก่อน
- **แก้โค้ดแล้วฟีเจอร์ใหม่ไม่ทำงาน** ปิดโปรแกรม (`/quit`) แล้วเปิดใหม่ Python ไม่รีโหลดโค้ดให้ process ที่รันค้างอยู่

## โครงสร้าง
```
run.py                  จุดเริ่ม (เช็ก venv + ตั้ง UTF-8 ก่อนเรียก src/app.py)
start.bat               ทางลัดรันด้วย .venv เสมอ
config.yaml             ตั้งค่าทั้งหมด
src/
  config.py             โหลด config.yaml + .env -> dataclass
  app.py                event loop หลัก: router -> (llm | claude | search | weather) -> tts -> avatar
  llm/
    client.py           คุยกับ LM Studio (OpenAI-compatible API)
    persona.py          system prompt / บุคลิก / คำสั่งมาร์กเกอร์
    router.py           แยก chat / ค้นเว็บ / อากาศ / ส่งงาน Claude
  tts/
    manager.py          แบ่งประโยค + cache (atomic write) + เลือกเอนจิน + แปลงคำอังกฤษเป็นไทย
    piper_th.py         Piper (ค่าเริ่มต้น)
    edge.py             Edge-TTS (online, คุณภาพสูงสุด)
    mms.py              MMS-TTS (fallback)
    f5_thai.py          F5-TTS-THAI (voice cloning, ช้า)
  avatar/
    vts_client.py       VTube Studio plugin API (WebSocket, requestID-matched RPC)
    driver.py           ยิงพารามิเตอร์ทุกตัวต่อเนื่อง 30fps (อารมณ์+ท่าทาง+กะพริบตา)
    expressions.py      ชุดค่าอารมณ์ + วิเคราะห์ฟอร์แมนต์เพื่อเดาสระจากเสียง
    lipsync.py          เสียง -> envelope ความดัง (RMS + noise gate)
    player.py           เล่นเสียง + ป้อนค่าปาก/สระเข้า driver แบบซิงก์เวลา
  web/
    search.py           DuckDuckGo + อ่านทั้งหน้าเว็บ + จัดอันดับความมีประโยชน์
    weather.py           Open-Meteo (geocode + forecast) ไม่ผ่าน LLM
  coding/
    claude_code.py       subprocess claude -p --output-format json
scripts/
  setup_check.py        เช็กความพร้อมทุกส่วน
  download_models.py    โหลดโมเดล TTS ล่วงหน้า
  bench_model.py        วัดความเร็ว/คุณภาพ/สัดส่วน reasoning token ของโมเดล LLM
  vts_auth.py           ขอ token VTube Studio แยกจากแอปหลัก (popup ค้างได้)
  vts_model.py          ดู/สั่งโหลดโมเดล Live2D ผ่าน API
  test_avatar.py        ทดสอบ connect -> พารามิเตอร์ -> ขยับปาก -> พูดจริง ทีละขั้น
```
